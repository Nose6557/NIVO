# NIVO

Тренажер англійської, що сам тримає твій рівень. Сесія — 15 завдань зі змішаних
категорій, після кожної відповіді пояснення українською. Інтерфейс український,
завдання англійські.

| Середовище | Адреса | Гілка | Хостинг |
|---|---|---|---|
| Прод | https://nose6557.github.io/NIVO/ | `main` | GitHub Pages |
| Тест | https://nivo-work.pages.dev | `work` | Cloudflare Pages |

Спочатку все їде на `work`, і тільки перевірене — в `main`.

---

## Що вміє

**Онбординг рівня.** На старті — самооцінка з п'яти формулювань без згадки CEFR
(аудиторія цих міток не знає) або тест на 16 питань. Тест зважений сходинковий:
крок угору `0.43`, крок униз `1` — бо «свій рівень» це ~70% влучань, а симетричні
кроки сходилися б до 50%. Перші чотири питання йдуть повним кроком, далі масштаб
`0.5` — спершу швидко звузити діапазон, потім точно довести. Правильну відповідь
під час тесту не показуємо: інакше це навчання, а не вимір.

**Адаптивний рівень A1–C2.** Рівень — одне значення, яке безперервно коригують
реальні відповіді. Деталі моделі — у [LEVELS.md](LEVELS.md). У меню аватара є
перемикач «Автоматичний рівень»: вимкнувши його, рівень можна зафіксувати руками,
і тоді додаток показує поруч свою чесну оцінку, але не втручається.

**Слабкі місця.** Кожне питання прив'язане до теми (`topic`), по темах копиться
статистика спроб і помилок. У звичайній сесії питання з гіршою темою випадають
частіше; кнопка «Тренувати слабкі місця» збирає сесію лише з проблемних.

**Переклад речення.** Поле `ua` показується під поясненням. На A1–B1 відкрите
за замовчуванням, вище — згорнуте; вибір користувача діє до кінця сесії.

**Синхронізація.** З акаунтом усе лежить у Supabase, без акаунта — в localStorage
того самого браузера. Гостьовий режим повноцінний, просто не переїжджає на інший
пристрій.

**PWA.** `sw.js` кешує оболонку: навігація і банки — network-first, решта статики —
stale-while-revalidate. Після першого завантаження працює офлайн.

**Аналітика.** Umami, підключена лише для домену `nose6557.github.io` — прев'ю
й локальний запуск у статистику не потрапляють.

## Структура

| Файл | Призначення |
|---|---|
| `index.html` | розмітка всіх екранів: вхід, відновлення пароля, головна, онбординг, гра, результат |
| `style.css` | оформлення, теми, анімації |
| `app.js` | логіка гри: завантаження банку, черга питань, рендер, підрахунок, меню рівня |
| `level.js` | модель рівня A1–C2 — рахує, нічого не малює |
| `onboard.js` | самооцінка, тест рівня, екрани підвищення/зниження |
| `ui/*.js` | UI-компоненти: `create<Name>(props)` → `HTMLElement`, лежать у `window.NivoUI` |
| `store.js` | єдиний шар доступу до даних: Supabase або localStorage |
| `config.js` | URL проєкту Supabase і publishable-ключ |
| `version.js` | єдине джерело версії оболонки: `NIVO_VERSION`, `NIVO_RELEASED` |
| `check.html` | валідатор банку — відкривається в браузері, нічого не збирає |
| `sw.js` | service worker: офлайн-оболонка, константа `CACHE` |
| `manifest.json` | PWA-маніфест |
| `_headers` | `X-Robots-Tag: noindex` для Cloudflare Pages |
| `favicon/` | іконки: `icon.svg`, `favicon-16/32/180`, `icon-192/512`, `icon-maskable-512` |
| `README.md` | цей файл |
| `LEVELS.md` | як влаштована модель рівня |
| `ROADMAP.md` | черга завдань |
| `.gitignore` | `.DS_Store`, `node_modules`, `storybook-static` |
| `stories/`, `.storybook/` | Storybook — вітрина компонентів з `ui/`, лише для розробки |
| `package.json`, `package-lock.json` | залежності Storybook; сам застосунок збірки не має |
| `banks/index.json` | маніфест банку: список паків, категорії, рівні, домени |
| `banks/*.json` | паки питань |

Порядок підключення скриптів фіксований: `version.js` → `config.js` → `store.js` →
`level.js` → `ui/*.js` → `onboard.js` → `app.js`. `version.js` має бути першим (з нього
беруться константи), `level.js` — до `app.js`, `onboard.js` — після `level.js`, а `ui/*.js` —
до `onboard.js` і `app.js`, бо обидва будують розмітку з компонентів. Усередині `ui/`
`token.js` іде перед `order-board.js`, `ua-toggle.js` — перед `feedback.js`.

## Формат питання

Пак — це схема 2: спільна шапка, словник тем і масив питань.

```json
{
  "schema": 2,
  "pack": "c1-03",
  "title": "Пак C1 — партія 3",
  "level": "C1",
  "topics": {
    "c1-syn-inversion-only": { "category": "syntax", "label": "Інверсія після Only then" }
  },
  "questions": [
    {
      "id": "c1-syn-inversion-only-03",
      "topic": "c1-syn-inversion-only",
      "level": "C1",
      "type": "mcq",
      "domain": "it",
      "prompt": "Only then ___ what the error message actually meant.",
      "options": ["did I understand", "I understood", "I did understand", "understood I"],
      "answer": "did I understand",
      "explain": "Only then — ще один тригер інверсії, як only after чи only when: did I understand.\n✗ I understood / I did understand — прямий порядок після Only then неможливий.\n✗ understood I — інвертується допоміжне дієслово, а не смислове.",
      "ua": "Лише тоді я зрозумів, що насправді означало повідомлення про помилку."
    }
  ]
}
```

Поля питання:

| Поле | Обов'язкове | Що це |
|---|---|---|
| `id` | так | унікальний на весь банк |
| `topic` | так | ключ теми; тема може бути оголошена в будь-якому паку |
| `level` | так | `A1`…`C2` зі списку `questionLevels` |
| `type` | так | `mcq`, `fill` або `order` |
| `prompt` | так | текст завдання; для `fill` має містити пропуск `___` |
| `explain` | так | пояснення українською, коротше за 40 символів — попередження |
| `answer` | так | правильна відповідь |
| `options` | для `mcq` | ≥2 варіанти, без дублів, `answer` має бути серед них точно |
| `tokens` | для `order` | ≥2 токени, що складаються рівно в `answer` |
| `accept` | ні | для `fill` — інші прийнятні написання; має містити саму `answer` |
| `ua` | ні | переклад речення під поясненням |
| `domain` | ні | тематична мітка; у грі поки не використовується |

Тема — це конкретне правило. Саме за `topic` рахується статистика слабких місць,
тому однакове правило в різних питаннях має мати однаковий ключ.

## Як додати пак

1. Створити `banks/<назва>.json` за схемою вище.
2. Дописати його в `packs` у `banks/index.json` (`file`, `level`, `title`).
   Нові категорії й теми — теж туди або в сам пак.
3. Відкрити `check.html` і домогтися **0 помилок**. Попередження можна лишати,
   але вони пояснюють, де банк перекошений.
4. Бампнути `NIVO_RELEASED` у `version.js` — з нього виводиться `BANK_VERSION`,
   яким збиваються кеші банків. Інакше GitHub Pages віддаватиме старі json.

## Деплой

Спершу завжди `work` — там прев'ю на Cloudflare Pages.

1. Залити файли.
2. Відкрити `check.html` — 0 помилок.
3. Пройти живу сесію: онбординг, 15 питань, результат, меню рівня.
4. Якщо змінилися колонки — виконати SQL у Supabase.

Потім мердж у `main`.

Версія живе в одному місці — `version.js`:

```js
const NIVO_VERSION  = "11";           // версія оболонки → CACHE у sw.js
const NIVO_RELEASED = "2026-09-24";   // дата релізу     → BANK_VERSION в app.js
```

| Що змінилося | Що бампнути |
|---|---|
| Будь-який свій статичний файл: HTML, CSS, JS | `NIVO_VERSION` |
| Тільки вміст `banks/` | `NIVO_RELEASED` |
| І те, й те | обидва |

`NIVO_VERSION` дає `CACHE = "nivo-v" + NIVO_VERSION` у `sw.js` — старий кеш видалиться
сам, інакше частина користувачів лишиться на попередній версії оболонки. `NIVO_RELEASED`
дає `BANK_VERSION`, яким `app.js` збиває кеш json-ів. Руками ці дві константи більше
ніде не дублюються, тож правити треба тільки `version.js`.

## Supabase

Таблиці, з якими працює `store.js`:

| Таблиця | Колонки |
|---|---|
| `profiles` | `id`, `level`, `level_source`, `level_locked`, `level_est`, `level_updated_at` |
| `sessions` | `user_id`, `started_at`, `finished_at`, `total_questions`, `correct_count`, `best_streak` |
| `answers` | `user_id`, `session_id`, `question_id`, `category`, `is_correct`, `response_ms`, `answered_at` |
| `weak_items` | `user_id`, `item_key`, `category`, `attempts`, `errors`, `last_seen` — унікальний ключ `(user_id, item_key)` |

Доступ обмежують політики RLS: користувач бачить лише свої рядки.

Колонок рівня в `profiles` може ще не бути — `store.js` це переживає: на помилку
про невідому колонку він тихо вимикає синхронізацію рівня і тримає його локально.
Тож файли можна заливати до міграції.

```sql
alter table profiles add column if not exists level            text;
alter table profiles add column if not exists level_source     text;
alter table profiles add column if not exists level_locked     boolean default false;
alter table profiles add column if not exists level_updated_at timestamptz;
```

**`level_est`** — оцінка рівня, яку додаток тримає окремо від самого рівня
(див. [LEVELS.md](LEVELS.md)). Ця колонка з'явилася пізніше за решту, тож для баз,
створених раніше, потрібна окрема міграція:

```sql
alter table profiles add column if not exists level_est text;
```

Без неї все працює, просто оцінка лишається локальною: `store.js` побачить помилку
про невідому колонку, вимкне синхронізацію саме оцінки — не рівня цілком — і більше
не смикатиме сервер.

**Ключі.** У `config.js` лежать Project URL і **publishable**-ключ — вони призначені
для клієнтського коду і публічні за визначенням. Секретний ключ (`sb_secret_...`)
сюди не потрапляє ніколи.

**Redirect URLs.** Щоб працювало «Забули пароль?», у Authentication → URL Configuration →
Redirect URLs мають бути всі адреси, з яких заходять:

```
https://nose6557.github.io/NIVO/
https://nivo-work.pages.dev
http://localhost:8000
```

Без цього посилання зі скидання пароля поверне користувача не туди.

На час тестування зручно вимкнути «Confirm email» у Authentication → Providers → Email.

## Локальний запуск

Через `file://` не запрацює: браузер заблокує `fetch` файлів банку. Потрібен сервер:

```
python3 -m http.server 8000
```

і відкрити `http://localhost:8000`. Валідатор банку — `http://localhost:8000/check.html`.

Локально ввімкнений service worker може віддавати стару оболонку — якщо зміни не
видно, вимкни його в DevTools → Application → Service Workers → Unregister.

### Storybook

Вітрина всього інтерфейсу окремо від гри: компоненти з `ui/` у всіх станах, кнопки,
поля, меню рівня, модалки й екрани цілком (група «Екрани»).
Потрібен Node.js; на сам сайт не впливає, збірки в застосунку як не було, так і немає.

```
npm install
npm run storybook
```

Відкриється `http://localhost:6006`. Stories лежать у `stories/<Name>.stories.js`,
стилі — той самий `style.css`. У тулбарі є перемикач теми: він ставить `data-theme`
на `<html>`, але тема поки одна — темна, тож це заготовка під світлу.

Розмітку, що лежить в `index.html` (вхід, меню, модалки), stories не дублюють, а беруть
із самого файлу: `pick(selector)` у `stories/markup.js` повертає копію справжнього вузла.
Зміниш розмітку в `index.html` — story оновиться сама.

Новий компонент: файл `ui/<name>.js`, який додає `create<Name>` у `window.NivoUI`,
рядок `<script>` в `index.html`, запис у `SHELL` в `sw.js` і story поруч з іншими.
